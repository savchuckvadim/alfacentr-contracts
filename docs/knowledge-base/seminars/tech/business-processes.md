# Бизнес-процессы Битрикса: кто что запускает

Часть логики живёт не в приложении, а в бизнес-процессах Битрикса. Их нельзя править через REST — только руками в дизайнере, потому что они созданы в дизайнере, а не приложением.

## На смарт-процессе «Семинары» (159)

| Процесс | Автозапуск | Что делает |
|---|---|---|
| `#664` Нумератор | нет | выдаёт номер договора по префиксу, работает со списком 46 |
| `#710` Нумератор v2 | нет | вторая версия нумератора |
| `#426` Реквизиты Семинары | на создание и изменение | тянет реквизиты, пишет в таймлайн |
| `#448` Редактирование Сделки | на создание и изменение | **только на стадии `PREPARATION`**: копирует товары, запускает другие процессы |
| `#520` email семинары | на создание и изменение | вопреки названию письма не отправляет; условие по служебному полю |
| `#780` Сумма повышенного предложения | на изменение | пересчитывает поля |

Важно при создании карточек программно: `#448` опасен только на стадии `PREPARATION`, поэтому служебные карточки создаются сразу закрытыми в `SUCCESS`.

## На сделке

| Процесс | Что делает |
|---|---|
| `#828` Сделка Семинары. Инициация заявки | вызывает бэкенд вебхуком при создании заявки |
| `#826` Сделка Семинары Есть товары? | проверяет наличие товаров |
| `#848` Семинары Отправить Документы | отправка пакета документов |

## Как нумератор в БП ищет счётчик

Не в списке 46, а через другую карточку смарта: активность «Получить информацию об элементе смарт-процесса» с фильтром «тот же префикс и непустой `LIST_ID`». Найдя карточку, берёт у неё `LIST_ID` и работает с этим элементом. Не найдя — создаёт свой элемент с номером 1.

Штатная активность «Получить информацию об элементе списка» умеет искать **только по ID элемента**, поиска по названию у неё нет. Поэтому научить бизнес-процесс искать в списке 46 по названию нельзя — вместо этого приложение создаёт карточку-якорь, которую бизнес-процесс найдёт.
