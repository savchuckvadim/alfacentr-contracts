# Типы и классификаторы: что на что влияет

В заявке пять разных «типов», и их постоянно путают между собой. Здесь — что каждый значит, где лежит, как определяется и что от него зависит.

Главное правило: **всё начинается с названия товара**. Тип товара, префикс и тип договора вычисляются из него, а не хранятся отдельными полями. Поправили название товара в каталоге — поменялось поведение всей заявки.

---

## 1. Тип товара

Базовый классификатор, из которого выводится всё остальное. Определяется по префиксу в названии товара — тому, что стоит после `[]`.

| Что есть в префиксе | Тип товара |
|---|---|
| `С`, и при этом нет `ППК`, `УВ`, `УП`, `УС` | семинар |
| `ППК` | ППК |
| `УВ` | УП видеозапись |
| `УП` | УП комплектом |
| `УС` | спецпродукт |
| ничего из перечисленного | семинар (запасной вариант) |

Порядок проверок важен, и первая строка сформулирована через отрицания намеренно. `УСР` содержит букву `С`, но это **спецпродукт**, а не семинар: у них разные договоры, и спецпродукт не должен проскочить как семинар. А `СР` — семинар.

Смысл букв в префиксе:

- **семинар** — `С` плюс отдел, дата и город: `СЗ2309СП` = запад, 23 сентября, Санкт-Петербург;
- **ППК, УП, УВ** — буква отдела (`Р`, `Н`, `З`) и год курсов: в 2026 году у всех `ППКН26`, `УПН26`, независимо от часов обучения и типа учреждения;
- **спецпродукт** — `УС` плюс отдел и год: `УСР` одинаков для здравоохранения и прочих учреждений.

У семинаров префиксы у всех разные, потому что собираются из отдела, даты и города. У ППК, УП и УВ отличаются только буква отдела и год.

---

## 2. Префикс

Лежит в названии товара после маркера `[]`:

```
Семинар РАЗРЕЗОВА 23-24 сентября Санкт-Петербург []СЗ2309СП
```

**Для номера договора** берётся префикс **одного** товара, не всех. Приоритет:

1. первый семинарный товар;
2. если семинаров нет — первый товар ППК;
3. если и их нет — первый товар УП;
4. если ничего не подошло — первый товар сделки.

То есть у сделки «семинар + ППК» номер будет с семинарным префиксом.

Префикс очищается автоматически: обрезаются пробелы по краям, неразрывные пробелы становятся обычными, невидимые символы удаляются, дефисы сохраняются. Без этого `СЗ2309СП ` с пробелом на конце был бы отдельным префиксом со своим счётчиком.

Влияет на: номер договора и счётчик в справочнике «Договор» (ID 46).

---

## 3. Тип договора

Вычисляется по **составу товаров сделки**, а не по одному товару. Проверки идут в этом порядке, первая сработавшая выигрывает:

| Условие | Тип договора |
|---|---|
| есть и семинар, и ППК | Семинар ППК |
| есть ППК | ППК |
| есть семинар | Семинар |
| есть УП комплектом | УП комплектом |
| есть УП видеозапись | УП видеозапись |
| есть спецпродукт | Спецпродукт |
| ничего не подошло | Семинар (запасной вариант) |

Влияет на:

- **форму договора** — у каждого типа свой шаблон;
- **приложение №1** — формируется только для ППК и Семинар+ППК;
- **таб «Приложение ППК»** — показывается только у этих же двух типов;
- **таб «Участники»** — скрывается у договоров УП;
- **тему письма** клиенту.

Обратите внимание: запасной вариант — «Семинар». Если товары подобрались неправильно, заявка молча уедет по семинарному договору. Поэтому предупреждения о неподобранных товарах игнорировать нельзя.

---

## 4. Тип заявки

Отдельное скрытое поле сделки **«Тип заявки»** (`UF_CRM_1771410918`), не вычисляется из товаров. Два значения:

- **Семинары**
- **Учетная политика**

Ставится формой, с которой пришла заявка. Разделяет два разных потока обработки: наш код работает с заявками типа «Семинары».

Не путать с типом договора: тип заявки говорит, *откуда пришло*, тип договора — *что продаём*.

---

## 5. Тип клиента

Поле сделки **«Тип организации»** (`UF_CRM_1744358047`), два значения: **Физическое лицо** и **Юридическое лицо**. Приходит из формы заявки.

Влияет на состав реквизитов и на текст договора: у физлица вместо ИНН и КПП — паспортные данные, адрес и телефон, и другая формулировка преамбулы.

При генерации документов используется более подробный классификатор: организация, бюджетная организация, ИП, физлицо, адвокат. Он определяется по реквизитам компании, а не по этому полю, и нужен шаблонам договоров.

---

## 6. Как подбираются товары

Приложение не догадывается о товарах — оно ищет их в каталоге CRM (ID 24) по полю товара **«Название в заявке»**, сравнивая с текстом из заявки.

Алгоритм на каждое название:

1. поиск по каталогу по вхождению текста;
2. **нашёлся ровно один** — берём его;
3. **не нашлось ничего** — товар не добавляется, менеджеру показывается предупреждение «не найден» с текстом, по которому искали;
4. **нашлось несколько** — включается подстраховка:
   - сначала ищем **точное совпадение** названия в заявке с запросом. Один такой — берём без предупреждения;
   - затем ищем те, чьё название **начинается** с запроса: так отсекается случай, когда значение из списка обрезано. Один такой — берём;
   - если и после этого не однозначно — **товар не вставляем** и показываем предупреждение «неоднозначно» со списком всех кандидатов.

Принцип подстраховки: лучше позвать человека, чем вставить не тот товар. Неверный товар меняет тип договора, префикс, номер и форму документов — ошибка уедет к клиенту.

Дальше по подобранным товарам:

- одинаковые товары **группируются**, количество считается по числу упоминаний;
- цена берётся **из каталога**, а не из заявки;
- строки добавляются с **НДС 5%, включённым в цену**;
- семинарные товары ставятся **первыми** — от порядка зависит, какой префикс уйдёт в номер договора;
- дубликаты по одному и тому же товару отсекаются.

## 7. Что ломается и как это увидеть

**Товар не подобрался.** Предупреждение в модуле: «не найден» или «неоднозначно», с текстом запроса и списком кандидатов. Причина почти всегда в поле «Название в заявке» у товара каталога: опечатка, лишний пробел, два товара с похожими названиями.

**Тип договора не тот, что ожидали.** Проверьте состав товаров и порядок проверок выше. Частый случай: товар не подобрался, сделка осталась без ППК-товара, и тип стал «Семинар» вместо «Семинар ППК» — приложение №1 не сформировалось.

**Спецпродукт ушёл как семинар.** Проверьте префикс товара: он должен содержать `УС`. Если там только `СР`, товар определится как семинар.

**Номер с неожиданным префиксом.** Посмотрите, какой товар в сделке первый по приоритету из раздела 2. Префикс берётся у него.
